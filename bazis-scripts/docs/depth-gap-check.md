# Проверка: внутренние не доходят до задней стенки

## Суть проблемы

У корпуса есть глубина (обычно ось Y или X). При увеличении глубины бока
и задняя стенка уезжают назад, а **полки / дно ящиков / зад ящика** часто
остаются на старой координате. Получается зазор «тыл полки ↔ плоскость задней
стенки», которого по задумке быть не должно (или он должен быть фиксированным,
например 2–5 мм).

Это не баг кромки и не баг материала — это **потеря параметрической связи
по глубине** между каркасом и начинкой.

## Что именно проверяем

Не «глубину шкафа», а **зазор по оси глубины** между:

- тыльной кромкой внутреннего элемента (полка, дно/короб ящика),
- рабочей плоскостью задней стенки (лицевая пласть задней, если она внутри,
  или плоскость четверти/паза — см. тип установки).

```text
бок L ──────────────────────────────┐
                                    │ задняя
полка  =======================> ????│   стенка
                                    │
бок R ──────────────────────────────┘
                         ↑
                   зазор = проблема, если > допуска
```

## Логика проверки (по шагам)

### 1. Выделить модуль

Работать не по всей модели сразу, а по **блоку/сборке** (один шкаф / одна
секция). Источник:

- текущее выделение пользователя, или
- корень `currentFileData.model`, если модуль один.

### 2. Классифицировать панели по роли

По ориентации нормали (ЛСК → ГСК) и положению в габарите модуля:

| Роль | Признак |
|---|---|
| Левый / правый бок | вертикальная панель, нормаль ≈ ±X (или ось ширины) |
| Задняя стенка | вертикальная/фронтальная, нормаль ≈ ось глубины, у «тыла» габарита |
| Полка / дно | горизонтальная, нормаль ≈ ±Z (ось высоты) |
| Фасад / перед | у «лица» габарита — обычно **не** участвует в проверке зазора к задней |

Имена (`ЛБ`, `ПБ`, `Зад`, `Полка`) — только как подсказка, не как единственный критерий.

### 3. Построить «опорную плоскость зада»

От задней стенки взять плоскость, к которой должны подходить внутренние:

- **накладная задняя** — передняя пласть задней (внутрь корпуса);
- **в четверть / в паз** — плоскость четверти/паза на боках (ещё надёжнее,
  но сложнее; v1 можно упростить до пласти задней).

Ось глубины `D` = нормаль этой плоскости (внутрь корпуса).

### 4. Для каждого кандидата (полка / ящик)

1. Взять габарит панели в ГСК (`GabMin` / `GabMax`).
2. Найти **тыльную** координату по оси `D` (край, ближайший к задней).
3. Посчитать зазор:

```text
gap = расстояние от тыла элемента до опорной плоскости зада
      (положительный = не доходит, отрицательный = врезается/заходит)
```

4. Сравнить с допуском:

| gap | Вердикт |
|---|---|
| `≈ expected` (± tol) | ок |
| `> expected + tol` | **не доходит** ← твой кейс |
| `< expected - tol` | пересекает / слишком глубоко |

### 5. Допуски (важно)

Один допуск на всех — плохо. Минимум два режима:

- **Полки / несъёмные** — обычно `expected ≈ 0…5 мм` (зазор под заднюю /
  вентиляцию). Всё, что больше (часто 20–100+ мм после смены глубины) — ошибка.
- **Ящики** — короб **намеренно** короче корпуса. Тут либо:
  - отдельный `expectedDrawer` (например глубина корпуса − 20…50 мм), либо
  - проверять только полки, ящики помечать отдельно / пропускать.

Без разделения полок и ящиков скрипт будет «рать» на нормальные ящики.

## Что скрипт должен выдать

1. Список проблемных панелей + `gap` в мм.
2. Выделение этих панелей в модели.
3. (Опционально позже) автопочинка: подвинуть/удлинить панель по оси `D`
   до `expected` — это уже вторая фаза, не проверка.

## Граничные случаи

- Несколько задних (антресоль, ниша ТВ) — нужна задняя **своего** отсека.
- Полка не на всю глубину **по задумке** (короткая полка) — исключение по имени/свойству.
- Корпус повёрнут — только через нормали/ЛСК, не через «всегда ось Y».
- Задняя из ДВП 3–4 мм vs фальшпанель 16 мм — меняется опорная плоскость.

## Минимальный v1 (рекомендую начать с него)

1. Пользователь выделяет блок шкафа (или работает с моделью целиком).
2. Находим одну заднюю (самая «задняя» вертикальная панель тонкая / по имени).
3. Берём все горизонтальные панели внутри габарита боков.
4. Считаем `gap` до передней пласти задней.
5. Если `gap > MAX_GAP_MM` (например 8) — в отчёт и выделить.

Ящики в v1 можно отфильтровать по имени (`Ящик`, `Box`) или по наличию
фурнитуры направляющих — иначе будет шум.
