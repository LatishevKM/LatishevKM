# Проверка: внутренние не доходят до задней стенки

## Суть проблемы

У корпуса есть глубина (обычно ось Y или X). При увеличении глубины бока
и задняя стенка уезжают назад, а **внутренние элементы** часто остаются на
старой координате по глубине:

- полки / дно;
- **вертикальные стойки** (перегородки между секциями);
- иногда короб ящика.

Получается зазор «тыл элемента ↔ плоскость задней», которого по задумке быть
не должно (или он должен быть фиксированным, например 2–5 мм).

Это **потеря параметрической связи по глубине** между каркасом и начинкой.

## Что именно проверяем

Не «глубину шкафа», а **зазор по оси глубины** между:

- тыльной кромкой внутреннего элемента,
- рабочей плоскостью задней стенки (внутренняя пласть / четверть / паз).

```text
бок L ─────┬────────────────────────┐
           │ стойка                 │ задняя
полка  ====│==================> ????│
           │                        │
бок R ─────┴────────────────────────┘
                              ↑
                        зазор = проблема
```

Стойка — такой же кандидат, как полка: у неё тоже есть габарит по глубине,
и тыльный край должен доходить до задней.

## Роли панелей

| Роль | Ориентация (нормаль) | Положение | В проверке зазора? |
|---|---|---|---|
| Левый / правый бок | ось ширины | край габарита по ширине | нет (это каркас) |
| Задняя стенка | ось глубины | у тыла габарита | опора, не кандидат |
| **Стойка** | ось ширины | **между** боками | **да** |
| Полка / дно | высота (Z) | внутри | **да** |
| Фасад / дверь | ось глубины / у лица | у переда | нет |
| Ящик | любое | внутри | отдельно / пропуск |

Ключ: стойка и бок **одинаково ориентированы**. Отличие только по позиции —
бок на краю ширины, стойка внутри.

```text
ширина →
[ бок L ] … [ стойка ] … [ стойка ] … [ бок R ]
   ↑ край                  ↑ внутри           ↑ край
```

## Логика проверки

### 1. Модуль
Выделенный блок / вся модель.

### 2. Оси
- `D` — глубина  
- `W` — ширина (`x`, если глубина `y`, и наоборот)  
- `Z` — высота  

### 3. Найти каркас
- задняя — нормаль ≈ `D`, самая «задняя»;
- бока — нормаль ≈ `W`, min/max по `W` (с допуском на толщину).

### 4. Кандидаты «начинки»
- горизонталь: нормаль ≈ `Z` (полки);
- вертикаль внутри: нормаль ≈ `W` и центр **не** на краю (стойки);
- минус имена-исключения (ящик, фасад…).

### 5. Зазор
Для каждого кандидата:

```text
gap = плоскость_зада − тыл_элемента   (>0 = не доходит)
```

Если `gap > MAX_GAP_MM` → в отчёт и выделить.

### 6. Допуски
- полки и стойки — один жёсткий допуск (например 8 мм);
- ящики — пропуск или свой `expectedDrawer`.

## Выход скрипта

Список проблемных с ролью (`полка` / `стойка`) и `gap` в мм + выделение.

## Граничные случаи

- Несколько задних (антресоль) — задняя своего отсека.
- Короткая полка/стойка по задумке — исключение по имени/свойству.
- Стойка не на всю высоту — на зазор до задней не влияет, проверяем только глубину.
- Корпус повёрнут — классификация по нормалям, не «всегда Y».

## Как сейчас определяется (v2)

1. Оси не захардкожены: ширина = ось с большим числом вертикалей.
2. Задняя: score = имя «зад» + тонкая (≤8 мм) + у края. Можно выделить вручную.
3. Внутренняя пласть задней = грань ближе к центру корпуса.
4. Бока = крайние по центру; стойки = остальные с нормалью ширины.
5. В конце — отчёт классификации. Если роли перепутаны — пришли текст отчёта.
